# 界面实现与预览验收

最后复核：2026-10-26
证据来源：三端维护约定、UI 契约、真实小样本预览、用户明确确认后测试的授权边界。

## 开工

1. 完整读取用户级 `peach-ui-consistency`，统一生产应用、官网与演示站的维护源、同步和预览交付。
2. 核对相关路由、已有控件与调用方。React 复用 BoardUI 与 Peach 组合件，遗留 DOM 复用 ui-kit；不要把遗留颜色、组件名称或 CSS 规则套到 BoardUI。
3. 检索项目记忆「界面预览与真实样本」，读取已登记入口；样本、来源核验、编辑保存按 `docs/UI_PREVIEW.md`。用户验收只用真实小样本与缓存，合成夹具用于隔离自动化测试。
4. 按下表只读相关章节。外部产品被点名参考时执行 `peach-reference-evidence`；未取得当前证据就明确未取得，不猜动画、间距或行为。

| 当前任务 | 参考 |
| --- | --- |
| 控件选择、颜色与组件体系 | `docs/UI_COMPONENT_CONTRACTS.md` 的「适用组件体系」「组件选择」「组件与视觉」，React 同时查 `docs/BOARD_UI.md` 对应条目 |
| 加载、进度、错误、成功与撤销 | 组件契约的「等待与回执」，文案按 `docs/WRITING.md` |
| 输入、菜单、弹层、确认与键盘 | 组件契约的「表单与浮层」，`docs/DESIGN_GUIDELINES.md` 对应章节 |
| 标签、播放器与导航异步状态 | 组件契约的「媒体与页面状态」及相关域实现 |
| 新布局、对齐参考、极端内容 | 设计准则、已登记的对应来源快照；只选本次相关轴，不要求读取全部参考集合 |

## 实现与预览

- 复用真实组件、语义 token 与既有编辑器；临时压力测试页或演示开关只留本任务工作树，交付前清理。
- 预览启动前取得 `scripts/check_ui_preview.py` 的成功 `real-ledger-subset` 报告，核对代码、数据、图像缓存与端口归属；来源未取得时不交付伪预览。
- 普通与编辑模式分别核对；每个交付页面提供指向同一代码、数据、路由的普通链接和 edit 链接，普通版在前，保留可访问服务。进入详情前关闭自动播放。
- 界面改动先构建并保留可访问的预览，提供地址；只有用户明确确认当前预览后才能运行测试，确认绑定该预览与范围，范围内沿用。发出地址、用户继续纠正和等待超时都不算确认；收到界面新纠正时停止本任务运行中及排队的测试，修好后重新等待确认。确认前只做实现、预览构建与视觉查看；用户明确只要图片时才仅提供截图。

## 验证与交付

1. 确认失败模式与现有覆盖，按 `docs/TESTING.md` 在组件、API 或浏览器层验证；代码冻结后运行一次 `auto`，不逐域重复全量。
2. 通用桌面和 390×844 不变量由正式 web 域执行，新路由接入 `frontend/e2e/smoke.test.ts`；几何和 computed style 问题先写可失败用例，语义行为不补源码措辞断言。
3. 人工浏览器留给新布局、参考对齐与观感判断，使用当前环境支持且符合用户偏好的浏览器入口，不把某个 CLI 的安装或历史权限行为设为固定前置。
4. 接口、sidecar 和算术可用严格校验项目 CA 的独立请求核对；布局、裁切、hover/focus 必须用浏览器证据。工具失败及时报告准确错误和未验证范围。
5. 同页所需状态先列全，再批量读取；不以进程就绪、静态通过或源码推断代替实图验收。搜索推荐词对真实 `/api/items` 核对命中，说明性后缀不混入关键词。
6. 按 `peach-surfaces` 核对真实影响，分别报告验证与生产状态；未切换不得称已生效。
