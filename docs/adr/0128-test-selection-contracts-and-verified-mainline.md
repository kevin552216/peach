# ADR-0128：按直接消费者与已验证主线选择回归

- 状态：已采纳
- 日期：2026-10-27
- 关系：将 ADR-0119 的已验证基线用于 GitHub Test；不改变 ADR-0127 的发行制品验收与晋级

## 背景

README 修改固定选择整个 tooling 域，双语文件改名还需修改调度器并触发全量。运行模块按名称取得功能域后，不再补入直接测试消费者，导致 HTTP 逻辑变化选不到已有的下载流量统计回归。未提交的删除状态在提交后退出快照，也会使内容相同的已验证结果无法直接交付。

## 决策

1. README 的 Python 下限与双语入口由 checks 中的安装契约核对。文档改动不选择整个 tooling；工具实现与工作流仍按其真实影响选测。
2. 已知运行模块的功能域与直接导入它的测试所属域取并集；未知范围、依赖、迁移、共享验证设施和执行模式变化保留全量。不无界遍历所有间接源码导入。
3. 测试文件的静态路径依赖以仓库根和已知别名为依据，不把临时仓库的同名写入当成真实输入。缺失文件不进入当前内容快照，删除仍由前后文件集合差异识别。
4. 正式入口不取得机器级资源锁。保留仓库全量证明与 Git 集成互斥、单轮分片及容器阶段，保护代码一致性与其他任务。
5. GitHub push 从最近成功且属于当前提交祖先的主线 Test 取基线，并把同一基线传给全部选测任务。失败后尚未验证的区间继续纳入差异；取证失败、无可用基线、未知影响和手动验证均全量。PR 继续相对其基线选测；发布演练与制品验收不缩减。

## 后果

普通文档提交仍检查文档契约、仓库规范和链接，不运行无关媒体与浏览器回归。共享模块可能选择更多业务域，这是补齐真实消费者的必要成本。直接导入分析不替代动态调用的显式登记；后续新增动态消费者须在对应回归中核对选测。

测试框架自身本批仍须全量验证；README 的可视化确认和提交声明继续适用。已公开提交保留历史，不为补充格式或来源关联改写远端。
