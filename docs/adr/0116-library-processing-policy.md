# ADR-0116：媒体库来源色与处理策略

状态：已采纳

## 背景

不同媒体库的整理程度差别很大：有的已经由整理工具配齐 NFO 与封面，联网补全只会消耗流量、还可能用外部结果替换本地图片；有的完全没有资料，要靠联网补全。原有做法只有全局开关 `metadata_only`（只管九宫格预览），无法按媒体库区分。

卡片原来也没有区分来源的方式。来源类型（本地、115、PikPak）不能当身份：同一类型可以有多个媒体库。

## 决策

来源色与处理策略都是媒体库一级的属性，存进 ADR-0115 的 `media.library_catalog.<library_id>`：

- `color`：界面强调色的键名，空表示不上色。后端只校验写法，色值由界面按键名取。
- `policy`：`auto`（自动补全）、`local`（仅使用本地资料）、`custom`（自定义）。`auto` 是默认值，不写进配置。
- `stages`：仅 `custom` 时存在，逗号分隔，取值 `probe`（读取视频信息）、`metadata`（联网补资料）、`cover`（联网补封面）、`people`（联网补人物图片）、`preview`（生成九宫格预览）。

三档的含义：自动补全做全部步骤；仅使用本地资料保留读取视频信息与生成预览，不做三项联网步骤；自定义只做所选步骤。三档都先读本地 NFO 与同目录图片，NFO 损坏、番号冲突、图片读不出照常报告。

处理流程只在现有闸口按作品所属根目录查策略，不另起机制。读取视频信息按根目录跳过；资料与封面按作品跳过对外部来源的询问；九宫格按作品跳过；人物资料与实体后继在没有任何媒体库允许 `people` 时整轮不派。定时扫描、增量入库与重试都经过 `process_library`，因此一并遵守。

界面的媒体库列表来自壳每次加载都会请求的 `/api/libraries`，卡片来源色读同一份，不另发请求；本机只缓存上一次的颜色供首屏铺色，以服务端为准。

## 后续

下列行为尚未实现，在后续变更中补齐并更新本文：

- 「本次跳过 / 以后也跳过」：本次跳过只影响当前任务并在续跑时保持；以后也跳过写入对应媒体库。
- 被策略跳过的步骤显示为「已跳过」，不算失败、不进入自动重试；恢复启用后允许补跑。
- 流量、磁盘与进度估算排除被跳过的步骤。
- 人物图片按人物所属媒体库细分：只出现在不允许 `people` 的媒体库里的人物不派头像与资料后继。
- 本地封面的候选、形状判断与保留门槛按「仅使用本地资料」调整（本地封面方案另行记录）。

## 代价

策略按根目录投影，作品换根目录归属时随之变化。自定义策略的步骤组合较多，界面只在选了自定义时展开步骤列表。
