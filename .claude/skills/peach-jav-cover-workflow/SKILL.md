# JAV 封面获取与验收

最后复核：2026-10-26
证据来源：封面获取与审计脚本、取景实现及测试、ADR-0107。

## 起跑

目标是取得可证明属于当前番号的最大合格封面，不写 ledger。保留 `cover-fetch-log.csv` 的来源与尺寸证据。先核对运行方式与已有同类进程，避免重复批次。

1. 用 `scripts/fetch_jav_covers.py --audit` 只读盘点缺失、损坏、解码与尺寸分布。
2. 先复用成功的元数据快照和上次日志的精确 URL，再查询缺少的官方候选；既有成功快照不重复请求。
3. DMM URL 变体由当前脚本生成；有 Prestige 厂牌证据才使用对应 MGS、Prestige 查询。按实际尺寸比较，不设置主机名固定优先级。
4. 反机器人拦截不绕过；DUGA 批量搜索需要应用 ID。Amazon 日本在真实 POC、身份无歧义并登记来源后才成为候选，放大图或水印不证明原始高清。

## 获取与替换

- 通过脚本的解码、身份、最小尺寸与图像类型检查后，按像素面积选择；同尺寸优先商品图。只在合格且更大时原子替换，失败保留原图。
- Range 读取先量尺寸，胜出后下载完整文件；JavDB 仅作核验证据，不安装、显示或作为缺图兜底。
- 单条网络异常记录失败并继续，确认无候选与瞬时失败分别保存；每条完成后持久化日志，磁盘与流量按 `peach-batch-jobs`。
- `--retry-misses` 重探缺失；`--upgrade-existing` 与 `--upgrade-max-width` 限定已有封面的升级范围，参数按当前脚本核对，批次额度不写成固定默认。

## 取景产物

取景算法、适用图像、边车契约与回归样例见 [封面取景](../../../docs/COVER_ARTWORK.md)，只在取景或边车任务时读取。源码中的版本与阈值是唯一真相，不在技能复制算法常量。

- 新封面补算 `scripts/detect_cover_faces.py` 与 `scripts/poster_crop_boxes.py` 的相应产物，原图保持完整；手工取景保留。
- 默认处理缺失、过期或尺寸不符的记录，只有明确全算时使用 `--redo`；写入与 `--apply` 先按脚本当前边界核对。
- 算法改变同步版本与消费者，先重算产物再切换适用服务；不能把取景坐标、安装封面与真实 ledger 写入混为一项。

## 验收

重跑只读审计，比较取得、保留、缺失、损坏与失败，抽查番号、精确 URL 和实际像素。代码按影响域走正式测试入口；分别报告代码、封面产物、适用服务与 ledger 状态。纯封面批次通常无需重启服务。
