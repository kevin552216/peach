# ADR-0125：安装包携带独立采集运行环境

- 状态：Accepted
- 日期：2026-10-24
- 取代：[ADR-0043](0043-amane-sites-via-thin-bridge-subprocess.md) 的决策三在桌面与 Docker 分发中的运行环境定位；源码部署仍使用数据目录的独立 venv。

## 背景

桌面应用和 Docker 面向直接安装使用。采集来源若在运行时依赖用户的 uv、Python、Git 或开发工具 PATH，应用即使能够启动，也可能无法取得资料。桌面进程继承的 PATH 还可能不包含终端中的 Homebrew 路径。

## 决策

1. 保留 ADR-0043 的子进程边界、来源链和独立依赖锁。Windows 与 macOS 通过主锁固定的 PyInstaller 构建独立 console 桥，Docker 在构建阶段准备独立 venv。
2. 所有桌面应用制品均保留完整采集运行环境，包括轻量安装包和应用更新包。版本、完整 revision 与程序相对路径写入随包清单；许可证、固定版本完整对应源码和依赖许可证一起分发。
3. 运行时优先使用匹配清单的随包环境。桌面或 Docker 的运行环境缺失、越界或不匹配时明确要求重新安装，不调用系统 uv，也不借用数据目录中的旧环境。
4. 桥子进程清除父应用的 Python 与 PyInstaller 内部环境，独立可执行文件按 PyInstaller 的新应用语义启动。
5. 构建自检清空 PATH，离线加载全部开放站点类。桌面制品验收同时核对运行环境自检与实际服务 API 返回的程序路径、版本和 revision；Docker 在断网容器执行对应检查。

## 后果

用户不需要准备采集依赖。安装包增加独立运行目录，构建时需要网络取得固定依赖与对应源码；来源站点的网络可达性仍由实际连接检查验证。源码部署继续按独立锁准备数据目录中的 venv，不将 amane 并入 Peach 主依赖树。
