# ADR-0114：云下载后处理在账本通道里先领

- 状态：已采纳
- 日期：2026-10-22
- 修订：ADR-0040「未决」里的后继优先级

## 背景

写账本的后继共用一条 `ledger` 通道，一次只跑一条（ADR-0040 第二条），按排队先后领取。
这条通道上有九种后继，其中取新作资料（ADR-0042 第六条）一批 24 部，来源连不上时每部要等满资料预算，
排着几批时要跑一到几个小时。云下载后处理排在它们后面，下好的文件要等这些后台批次跑完才认正片、
写番号、整理入库，而这正是用户刚做完、在等结果的那件事。

## 决策

**一、后继类型可以声明 `jumps_queue`。** 带这一项的后继在自己的通道里先于别的种类领取，
同一档里仍按 id 先排先跑。在途那一条不打断，插队只决定下一条领谁。

**二、目前只有云下载后处理插队。** 判据是「人刚做完一件事、在等它收尾」；补资料、补头像、
补样张这类后台存量不插队。新增插队的种类要能说出用户在等什么。

## 后果

- 下载后处理最多等通道上在途的那一条跑完，不再等整队后台批次。
- 云下载连续涌入时，后台批次会被推后；下载是用户一部部发起的，量有上限，不会把后台批次饿死。
- 通道仍是串行，账本写锁的约束不变。
