# ADR-0124：amane 独立运行环境与自动准备

- 状态：Accepted
- 日期：2026-10-23

## 背景

amane 提供默认来源链中的片商官网、MGStage 等解析能力。全新部署必须取得这一能力，采集任务才能按完整来源链工作。独立运行环境的准备属于 Peach 初始化职责。桌面用户不应额外安装 Python、uv 或 Git。

## 决策

沿用 ADR-0043 的子进程、固定 revision、独立依赖锁和 Peach 来源结算边界。以下分发与准备方式作为运行环境契约：

1. Windows 与 macOS 制品按桥锁创建独立构建环境，用项目既有 PyInstaller 构建独立桥程序。Docker 在镜像构建阶段预装独立 venv。清单包含完整 revision、amane 版本、程序类型与目录内相对路径，运行时只采用与 Peach 清单匹配的环境。
2. 源码与 wheel 在首次实际需要 amane 时按锁自动安装，安装目录位于数据目录的工具区。FileLock 串行化并发安装，锁内复查安装结果。完整环境按固定 revision 复用，半安装环境保持未就绪。
3. 安装下载使用 Peach 代理。直接连接清除子进程环境代理，并显式覆盖 Git 本次调用的代理配置；自定义代理传给 uv 与 Git；跟随环境保留进程设置。错误回执脱敏，不更改用户机器的 Git 配置。
4. 馆藏采集在逐片联网前准备本趟需要的工具，准备时间独立于单片来源查询预算。准备失败集中记录一次问题，保留依赖该工具的资产范围，其他项目继续处理；用户修复后可重试。仅扫描、本地处理和不包含 amane 的来源链不触发安装。
5. 首次设置页提供 Peach 代理，保存先于首次扫描和采集。设置页继续允许重新安装固定版本；上游版本只供检查，不自动追随。
6. 随包保留 GPL 许可证、对应 revision 的完整来源与构建入口。新增制品必须在无网络自检中载入桥运行时和开放站点的解析器；镜像验收使用空数据卷。

## 验证边界

临时目录与临时账本覆盖代理继承、并发安装、失败回执、待处理范围及重试。桌面桥构建后执行无网络自检。跨平台制品及 NAS 实机行为分别报告；本机单元测试不能替代目标系统的发行验收。
