# ADR-0126：升级时自动处理存量资料与派生缓存

- 状态：Accepted
- 日期：2026-10-25
- 关联：[ADR-0040](0040-tasks-declare-followups-at-the-end.md)、[运行与配置](../OPERATIONS.md#升级后的自动处理)

## 背景

程序中的修正规则只会影响再次执行对应逻辑的项目。已有资料、完成记号、负面缓存、九宫格与浏览器中的旧页面可能继续沿用既有结果。升级需要同时覆盖结构迁移、存量资料、派生文件及独立安装的用户脚本。

## 决策

1. 已配置的本机写入端启动时，先备份并执行结构迁移，再处理本地确定性资料，最后恢复后台任务。只读端不迁移、不登记补修任务；未知迁移版本与校验不一致均拒绝写入。
2. `upgrade_rules` 集中登记资料、处理检查点、来源证据与派生缓存的规则版本。影响既有结果的修复须推进对应规则版本，并提供临时账本或缓存的行为回归。应用版本号与规则版本分别维护。
3. 本地资料补修复用已有番号、r18 文字与复合别名修复。番号沿用已保存的自定义识别规则；人工字段、复核归属及人工规范名受保护。冲突与合并候选写入复核产物，不自动决定身份合并。
4. 补修结果与账本标记在同一事务提交，派发记录写入同一标记，外部回执作为读取副本。数据库恢复后以账本标记判定是否需要处理；损坏回执保留副本并按账本恢复，无法读取记录时报告失败。每次实际处理前保留数据库备份，核对完整性及新增外键违规。
5. 联网资料和媒体补全复用任务后继、来源冷却及断点。自动媒体读取只选择免费来源，遵守媒体库处理方式和预览设置；额外流量项目延后。用户取消的任务保持取消，失败项提供显式重试。随包种子内容变化可独立触发导入。
6. 派生图按规则与来源文件代际签名失效；生成前后核对同一来源。公开快照、来源证据、负面结果及浏览器持久缓存各按其规则版本复用。原图、媒体与人工选择不做批量清退。
7. 浏览器读取本机更新快照，分别提示有新版本、更新准备完成和当前页面需要刷新。用户明确点击后才刷新。用户脚本独立检查可信发布元数据，匹配页在未识别番号或未配对时也提供入口；不把 Peach 令牌发送给公开发布源。
8. 独立包安装在新程序通过健康及结构检查后才放行后台任务。写入端安装前保存配置、账本和恢复检查点，失败时一并恢复。读取端仅安装结构兼容的程序，不预约写入任务、不备份或回写账本；存在待迁移结构时，须先在写入端完成迁移并同步。「自动修复」面板仅展示自动处理状态、复核入口和失败重试，不作为升级生效的前置操作。

## 后果

升级的成功判据包含存量效果。首次处理会产生备份和后台工作；失败与冲突保留可追踪状态。正在运行的旧版浏览器页面与用户脚本需要刷新才能加载新代码，应用只提示，不强制打断操作。

已经安装的旧更新器无法由新程序追溯修正，仍遵守 [独立包兼容边界](0120-standalone-update-client-compatibility.md)。旧读取端助手在新 CLI 拒绝迁移后可能恢复账本备份，不能保证该首次升级路径零写入；须先由写入端迁移并同步，读取端再升级兼容程序。当前应用更新也不能替脚本管理器完成独立脚本安装。
