# 上下文归属与清退

最后复核：2026-10-26
证据来源：ADR-0015、预算检查器、规则与实现对照审查、用户确认的精简范围。

## 判定归属

按 [ADR-0015](../../../docs/adr/0015-agent-context-layering.md) 判断：

1. 各类任务都可能触发，遗漏会损坏真实数据、生产或结论：项目入口留短边界与可执行入口。
2. 某类任务的执行顺序、判断与停止条件：对应项目技能。
3. 通用用法、字段、组件规范、算法与设计理由：文档、实现或 ADR，技能按任务路由到章节。
4. 跨项目偏好与边界：用户级入口；成套流程进入用户级技能，机器事实进入按需参考。
5. 单次任务、部署事实、个人待办与复核记录：仓库外数据根。

规则必须对应可指认的项目失败或用户决策，上游材料只作证据。保留约束防住的后果；案例只选能改变判断的坏例与好例。

## 编写与检查

- 同一事实维护一处，不复制实现常量、完整覆盖清单和安装手册。只读当前模式需要的参考，不把整套参考变成必读。
- description 只写触发与边界；与项目索引一致，不用泛化关键词吸引无关任务。
- 技能不新增审批，不删除真实数据、凭据、外发、预览确认与生产入口的既有边界。
- 可稳定检测的失败由脚本、测试或 hook 强制；语义判断留在指令中，不声称技能触发本身是门槛。
- frontmatter 使用目录同名的 `name` 与 `description`，正文写复核日期和证据来源；新增技能同步项目索引。
- 预算唯一真相在 `scripts/check_context_budget.py`。现有预算不因写超而抬高；变更须说明职责无法下沉的理由并遵守天花板。
- 中文与最终状态写法、检查覆盖、词表与事故例外按 [WRITING.md](../../../docs/WRITING.md)。

## 复核与清退

相关实现变化、同类失败重复、预算失败或 minor 发布前：

1. 读取当前实现、测试与准确错误；有证据缺口才查历史，不按模型名称批量删除约束。
2. 删除失效条文，把重复内容合并到所属位置，同步修复引用和触发范围。
3. 核对数据、候选、生产、预览与进程保护边界，避免用绝对化短句改变授权语义。
4. 更新实际复核过的日期，运行预算检查并通过项目测试入口验证相关域。
5. 用文档小改、行为修复和真实数据操作等代表性请求检查路由、停止条件与交付范围。静态通过不证明模型效率改善。

预算检查退出码：0 为通过，1 为结构或预算错误，3 为仅复核超期。耗时偏离预期时核对无关读取、重复验证与授权歧义，不新建定时任务规避本轮交付。
