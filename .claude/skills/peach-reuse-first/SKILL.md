# 复用与实现范围

最后复核：2026-10-26
证据来源：ADR-0010、`docs/REUSE.md`、FANBOX 与浏览器数据复用事故、用户确认的复杂度与调查停止条件。

## 选择路径

1. 按能力搜索当前树、`docs/REUSE.md`；有证据缺口再查 Git 历史，不以旧文件名缺失判断能力不存在。
2. 已有实现覆盖需求时直接复用，验证本次差异后停止调查；局部修复不自动触发外部依赖评选。
3. 确需新基础能力时比较官方协议、SDK、维护中的库与系统能力；实际候选核对维护、许可、固定版本、平台兼容、体积与已知故障。
4. API 定义不足以决定方案时才读候选源码，可用已安装的 `opensrc`，不把工具安装设成固定前置。
5. 用无真实写入的最小 POC 验证会改变选型的约束。Cookie、token、查询凭据与真实内容不进入日志或公开文档。

成熟依赖覆盖基础能力时只保留 Peach 领域 policy 和 DTO；复用开源模型或算法固定 revision 并遵守许可。外部方案不满足已验证约束时保留自研，在 `docs/REUSE.md` 说明理由。

## 复杂度边界

- 新兜底、重试、兼容或竞态分支须有可触达输入、失败结果与依据；无依据的理论分支默认省略，必要的范围扩展由用户决定。
- 未知输入在负责的边界校验，内部沿用已成立的类型和契约；新信任边界仍须校验。失败与无结果分别表达，不用默认值伪造成功。
- 单次使用的 helper 在表达独立概念或隔离复杂边界时才抽；注释说明非明显约束及后果。
- 实体身份、跨来源绑定、凭据隔离、候选复核、任务语义与交互属于 Peach 差异；通用传输、解析、锁、媒体编解码与控件优先复用。

## 交付

新增依赖、首个消费者、行为验证、锁文件与复用记录同批提交，不提前引入未来消费者。报告采用实现、领域差异、关键拒绝理由与实证；没有新增选型时不重做整份调查。
