# ADR-0127：从成功演练晋级发行产物

- 状态：已采纳
- 日期：2026-10-26
- 关系：修订 [ADR-0121](0121-release-rehearsal-and-atomic-publication.md) 的标签重新构建与演练回收方式

## 背景

演练和标签分别构建时，标签仍会遇到源码下载与上传故障。已经构建成功的文件也可能因最后的清单上传失败而需要重建。重复媒体编译、打包和安装验收增加发布时间，两个流水线分别暂存还会增加发布桶峰值。

## 决策

版本提交仍执行三平台正式回归、媒体编译、桌面制品安装与升级验收、Docker 冒烟。演练全部成功才允许创建标签。标签核对同一提交后晋级已验收产物，不重新构建，也不删减演练中的验证。

GitLab 的产物按项目、流水线、完整提交、版本和生成作业隔离。每组文件完整上传后，在同一暂存前缀登记不可变完成清单；文件大小、SHA-256、路径与来源身份同时受检。作业重试可以恢复该流水线已经完整上传的文件，网络失败与尚无完成清单分别处理。`seal-release` 在全部必需任务成功后登记候选清单。标签必须核对最新成功演练的任务标识、候选来源和文件摘要，缺失、过期或身份不符时停止。

R2 上传前，把完成构建的字节和清单保存在 `CI_BUILDS_DIR/.peach-upload-resume/` 的同项目、流水线、提交与产物组目录。传输失败后优先核对这份备份并续传到原生成作业前缀，不重新构建；远端完成清单登记成功后删除本组备份。备份缺失、机器已更换或文件校验失败时分别报告，不把网络失败当作没有构建结果。

GitHub 从相同提交、主线推送触发的成功 Release 演练读取产物。必需的构建和制品验收任务须成功，产物须未过期且具有服务端 SHA-256；下载后核对摘要再展开。镜像保存为演练产物，发布前核对加载后的 image ID、版本与提交。REST 请求使用 CI 提供的短期令牌，跨主机下载重定向移除认证头。

GitLab 的 Docker 候选镜像保留在完成演练的 Windows runner，清单记录 image ID。发布必须取得同一个镜像及对应提交、版本，镜像丢失或被替换时停止，重新执行演练。桌面文件与 GitGud Release 就绪后才推版本镜像和 `edge`，发布顺序沿用 ADR-0121。

## 容量、缓存与回收

构建前读取发布桶真实占用并列出暂存范围；构建清单齐备后、Windows 安装冒烟前计算包含暂存和公开版本副本的精确峰值。候选登记与正式上传仍复查预算，不把尚未构建的版本大小当作已知值。清理历史暂存和调整预算仍需独立审阅，不自动删除既有公开版本。

演练候选保留到桌面与镜像发布全部成功。最终回收任务核对公开版本索引和同一成功演练，只删除该演练暂存前缀。发布失败保留候选，以便重试传输阶段。

媒体工具缓存包含二进制、许可证和对应源码包。缓存身份覆盖固定源码清单、构建脚本、平台、架构、部署目标和工具链，命中后逐文件核对 SHA-256；缺文件、内容损坏或输入改变时重建。缓存不是发布成功证明，应用和镜像的独立验收照常执行。

## 边界

本决策不改变终端用户数据库、数据目录、更新清单或安装协议。现有安装通过原有升级路径取得发行文件。网络出口和账号托管不在本决策中更改。

演练产物过期、受保护凭据不可用或候选镜像丢失时，不临时拼接其他流水线文件，也不放宽摘要检查。应重新完成同一版本提交的演练，再发布其完整产物。
